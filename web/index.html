5 · 另一套方案：§8.1 的 VDS1（能派生新文件）

上面整条流程是 §8.2 的 VDS2：承诺与打开各一个群元素，但 没有「从一个已存文件里派生出新文件」的能力。 §8.1 的 VDS1 多花一个群元素（承诺变成一对累加器 (A, B)），换来 CreateFrom / GetCreate： 只存了文件一部分的节点能派生出新文件，客户端只用一个常数大小的 PoKSubV' 证明就能核实「新摘要确实是原文件那一段」。

下面这个按钮会现场建一份独立的 VDS1 会话（与上面的状态无关）， 跑完：Bootstrap → 提交 → 分发 → 检索聚合验证 → 派生新文件 → mod / add / del（每步都给 I ∩ K 三种情形各造一个探测节点） → 四类攻击。
