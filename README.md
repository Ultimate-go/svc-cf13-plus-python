## 这是什么

一个文件被切成若干块，分散存在**互不信任**的多台服务器上。任何人想要其中若干部分时，
服务器把**内容**连同**证据**一起返回。核心能力有三条：

| 能力 | 含义 |
|---|---|
| **常量摘要** | 客户端只保存 `δ = ((U, C), n)` —— 两个群元素 + 一个整数，与文件大小无关 |
| **常量证据** | 一次打开的证据是 `π_I = (S_I, Λ_I)` —— 两个群元素，与打开多少块无关 |
| **增量聚合** | 从多台服务器拿到的多份证据能合成**一个**；合并结果仍是合法证明，可无限次继续合并 |
| **存储证明** | 不下载任何内容，也能确认全网确实还存着文件（附录 D.1 的 PoR/PDP） |
| **可验证更新** | 增删改走两段式：持有改动内容的一方产出更新密钥 `Υ∆`，其他节点**无需该内容**就能校验并跟上 |

验证代价与块数、文件长度**无关**：客户端拿到聚合后的那一个证据，
用自己手里的摘要一次校验就完事。

看到摘要、每台服务器的状态、检索到的多份证据、聚合后的唯一证据、验证结果；

> 演示建议把 **模数位长设成 512**，速度差两个数量级。
> 512 位只够跑通代数关系，**没有任何安全强度**；真实部署需要 2048 位以上。

## 方案速览

记号：`e_i` 是第 `i` 个 `(l+1)` 比特素数，`e_I = ∏_{i∈I} e_i`，`e_[n] = ∏_{i=1}^{n} e_i`。

```
Setup(1^λ, ℓ, n)   →  crs = (N, g, PrimeGen, ℓ)
Specialize(crs, n) →  crs_n = (crs, U_n, e_all)，U_n = g^{e_[n]}

Com(crs_n, v)      →  S_i = g^{e_[n]/e_i}
                      C   = ∏_i S_i^{v_i}          ← 单个群元素
                      aux = v                       ← 原始数据

Open(crs_n, I, y)  →  S_I     = g^{e_[n]/e_I}
                      Λ_I     = (∏_{j∉I} S_j^{y_j})^{1/e_I}
                      π_I     = (S_I, Λ_I)          ← 两个群元素

Ver(crs_n, C, I, y, π_I)
                   ①  S_I^{e_I} = U_n               ← 锁死 S_I 必须是那一项
                   ②  S_i = S_I^{e_{I\{i}}}          ← 从 S_I 现场重构
                   ③  C = Λ_I^{e_I} · ∏_{i∈I} S_i^{y_i}

Disagg(crs_n, I, v_I, π_I, K)  →  π_K               ← 大集合拆小
Agg(crs_n, (I,v_I,π_I), (J,v_J,π_J))  →  π_{I∪J}    ← 小集合合大
```

**为什么公开参数是常数的**：CF13 原方案要把 `S_1, ..., S_n` 全放进公开参数。
这里只放一个累加器 `U_n = g^{e_[n]}`，验证方靠 `S_I^{e_I} = U_n`
一次模幂就锁死了 `S_I` 的合法性 —— 于是参数从 `O(n)` 降到 `O(1)`。

**为什么 `1/e_I` 次方能公开算**：`S_j^{1/e_I} = g^{e_[n]/(e_j·e_I)}`。
只要 `j ∉ I`，两个下标集合不相交，`e_j · e_I` 就整除 `e_[n]`，
指数是**整数**，直接模幂即可 —— 我们并不需要知道群的阶。

**聚合为什么需要「除交叉项」**：`Λ_I` 里属于 `J` 的那部分是 `1/e_I` 次方，
而 `Λ_{I∪J}` 里应该是 `1/(e_I·e_J)` 次方，次数不匹配，直接相乘会重复计数。
所以要先算 `ρ_I = Λ_I / ∏_{j∈J} φ_j^{v_j}`（群除法），再用 Shamir 技巧合并。

### 一个统一视角：证明就是摘要

上面的算法可以收到一个更本质的观察下（见 `docs/与论文对照.md`）：

> **子向量打开证明 `π_I` 就是「去掉 I 之后那个向量的摘要」。**

写成公式就是 `π_I = d(v \ I)`，其中

```
d(v) = (S, Λ),   S = g^{e_[n]},   Λ = ∏_{i∈[n]} (S^{1/e_i})^{v_i}
```

于是：

| 操作 | 在新视角下 |
|---|---|
| **承诺** | `d(v \ ∅) = (U_n, C)` —— 两个分量就是摘要的两个分量 |
| **打开** | `d(v \ I) = (S_I, Λ_I)` —— 同一个函数换个 `excluded` |
| **拆分** | 逐个把 `I \ K` 里的位置「加回」摘要 |
| **验证** | 把 `I` 全部加回去，看是否正好变回 `d(v) = (U_n, C)` |
| **追加新位置** | 对 `d(v)` 加回一个位置，就是 `S' = S^{e_{n+1}}, Λ' = Λ^{e_{n+1}}·S^{v_{n+1}}` |

「加回」这一步只有一个公式：

```
(S, Λ) ← (S^{e_i},  Λ^{e_i} · S^{v_i})          # 注意 S^{v_i} 用的是更新前的 S
```

代价 `O(ℓ)`。整个方案里 **拆分、验证、向量扩展三件事都只是把它循环若干次**。

## 实现要点

### 三处必须用分治的地方（否则规模一上去就不可用）

| 位置 | 朴素做法 | 本实现 |
|---|---|---|
| 一次算出所有 `S_i` | `n` 次「指数有 `(n-1)(l+1)` 位」的模幂 | `batch_root_factor`，分治 |
| `e_all = ∏ e_i` | 顺序连乘，`O(n²)` | `product_tree` 平衡树，`O(n log n)` |
| `d(v \ I)` | 对每个 `j∉I` 单独模幂 | `weighted_root_product`，一次分治 + 小指数加权 |

### 三处靠「加回」从平方降成线性

| 操作 | 重构前 | 重构后 |
|---|---|---|
| `verify(crs_n, C, I, y, π_I)` | `reconstruct_s_i` 逐个重构 `S_i`，每次指数 `(\|I\|-1)(l+1)` 位 → `O(ℓ\|I\|²)` | 顺序 `add_back`，每次指数 `(l+1)` 位 → `O(ℓ\|I\|)` |
| `disagg` | 需要一次 `root_factor` → `O(ℓ\|I\K\|log\|I\K\|)` | 顺序 `add_back` → `O(ℓ\|I\K\|)` |
| `disagg_one_to_many(n, B)` | 每块单独从原证明拆一次 → `O(n²/B · log)` | 递归二分 → `O(n log(n/B))` |

实测对比（`n = 1024`、`\|N\| = 1024`、`l = 32`）：

| `\|I\|` | 重构前 `verify` | 重构后 `verify` | 加速 |
|---|---|---|---|
| 8 | 20.2 ms | 4.6 ms | 4.4× |
| 32 | 198.3 ms | 18.7 ms | 10.6× |
| 128 | 3018 ms | 76.2 ms | **39.6×** |
| 512 | 47502 ms | 310.6 ms | **152.9×** |

重构后的 `verify` 是严格的线性：`|I|` 从 4 涨到 512 时，
单位元素代价稳定在 ~550-600 μs（相当于每步常数个 `(l+1)` 位指数的模幂）。

### 双路径互验

清单原文：*「前期使用 13（逐项算 `S_i`）进行 debug，这里的 8（批量求根）算大量内容更快，
但是出错不好修」*。所以 `commit` / `lambda_subset` 都提供 `use_batch` 开关，
**两条路径的结果必须逐位相同**（见 `tests/test_scheme.py::test_批处理与朴素路径一致`）。

### 聚合必须与直算比对，不能只验「能不能通过」

一个把 `Λ` 算错但在其他地方凑巧抵消的实现，也可能让「聚合后能验证通过」这条测试通过。
所以 `tests/test_agg_disagg.py` 的所有关键用例都是：

```python
assert 真聚合的结果 == 对新集合从零算一遍的结果
```

### 素数映射的互异性是硬前提

`shamir_trick` 在 `gcd(x, y) ≠ 1` 时会**静默返回错误结果**（不崩溃，只是算错）。
所以：

* 默认走 `PrimeGen`（**双射**：从 `2^(bits-1)` 向上扫描，天然无碰撞）；
* 哈希版 `PrimeGenHash` 默认开启碰撞检测，一旦碰撞**立刻抛异常**；
* `PrimeGen` 在「该位长素数已用尽」时**抛异常**，而不是悄悄返回位长超标的素数
  （后者会让论文里所有基于位长的安全性分析失效，且极难在测试中发现）。

## 性能提示

模幂是唯一的瓶颈，而 CPython 的 `pow(a, b, n)` 已经是 C 实现的
（用 Karatsuba，不是 GMP 但同一量级，约 **20 μs/指数比特** @ 2048 位模数）。

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `Setup` | 一次 RSA 模数生成 | 2048 位约 3~5 s |
| `Specialize` | **一次**指数有 `n(l+1)` 位的模幂 | `n=2^16, l+1=129` 时指数 840 万位 → 数十秒 |
| `Commit` | 一次分治 + `n` 次小指数模幂 | |
| `Open` | 一次分治 | |
| `Verify` | 3 次模幂 | **与 `n` 无关** |
| `Agg` | 2 次 Shamir + 2 次分治 | 与**被合并的块数**成正比，与 `n` 无关 |

想跑更大规模，请看 `bench/bench_scale.py`（默认参数很小，自己调）。
